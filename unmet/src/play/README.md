# The game (`/unmet/play/`)

A live guess-then-reveal game on the Unmet data and map. Each round asks about one country and one basic need ("Out of 100 people in Nigeria, how many have electricity at home?"); everyone guesses, then the truth appears with the room's guesses around it. Some rounds put two countries head to head; the last round counts double. At the end: a podium, awards, and what each player's guesses say about how they picture the world.

Three ways to be on the page:

| | |
| --- | --- |
| **Host** | "Host a room" opens a room with a four-letter code, a join address and a QR code. Meant for a big screen; a host on a phone can play too. |
| **Player** | Types the code (or opens the link, or scans the QR), enters a name, and is in. No account. |
| **Solo** | "Play today's five": the same five questions for everyone each day, a shareable result, a streak. Needs no back end. |

It is a second standalone document built next to Unmet (`unmet/dist/play/index.html`). Unmet itself is untouched; the game imports Unmet's `map.js`, `model.js`, `needs.js` and `i18n.js` and shares its fonts, map files and data snapshot.

## Try it locally

```sh
npm run unmet:dev
# http://localhost:5176/unmet/play/?mock
```

`?mock` keeps rooms inside your browser, so you can open several tabs (one host, a few players) and play a whole game with no Firebase. `?mock&admin` shows the admin screen and saves to that browser only. Without `?mock` the page talks to the real project.

## Going live

1. **Deploy** the usual way. Three things ride along that were not there before:
   - `database.rules.json` has a new `play` block (the rooms).
   - `firestore.rules` has three new collections: `playSettings`, `playLeads`, `playGames`.
   - `firebase.json` has redirects so `yoursite/play` and `yoursite/play/CODE` reach the game, and a rewrite so `/unmet/play/CODE` opens it.
2. **Functions**: `playLeadCreated` (in `functions/src/play.ts`, exported from `functions/src/index.ts`) sends the result email. Deploy it with the rest of the functions. Until it is deployed, emails are still collected, just not answered. The link in the email opens `/signup` with the player's name and email filled in (see `ngOnInit` in `signup.component.ts`).
3. **Smoke test** on the real site: host a room on a laptop, join from a phone, play one game, leave an email. The room rules have been tested offline against a rules simulator (see below) but not yet against the live database.
4. Nothing to switch on in the Firebase console. Rooms use the Realtime Database with **no sign-in**, so the game adds no users to Firebase Auth and never touches the main site's session.

## Admin settings

Open `/unmet/play/?admin` (or the "Admin" link in the footer) while signed in to the main site as a platform admin. Saved to Firestore at `playSettings/main`; every visitor picks them up on their next page load.

| Setting | What it does |
| --- | --- |
| Game name (and French name) | The wordmark, the browser tab, the email subject. Default "Out of 100" / "Sur 100". |
| Line above the headline, lobby message | Optional text, e.g. "Welcome, ENTP 601" on every lobby. |
| Address people type | The domain on the big screen, in links and in the QR code (e.g. `globalsolutionlab.com`). |
| Short links | `site/play/CODE` instead of `site/unmet/play/?r=CODE`. |
| QR code in the lobby | Default for new rooms; a host can still toggle it. |
| Rounds, seconds, move on automatically, most players | Defaults for new rooms; a host can change rounds, seconds, region and topics in their lobby. |
| Extra words to refuse | Added to the built-in list for player names. |
| Offer "email me my result", where the link goes | The end-of-game email ask. Turn it off for groups of children. |
| Daily solo game | Show or hide "Play today's five". |

The same screen lists the emails players have left (with a CSV download) and recent games.

A host has their own controls in the lobby: click a player's name to rename or remove them, lock the room, pick the region and topics, hide the QR code.

## How a room works without sign-in

Each device makes itself an identity once: a public id and a secret key, kept in `localStorage`. A room has a public half anyone can read and a secret half no one can read:

```
play/rooms/{CODE}/pub   host, cfg, state, players, guesses, scores, final
play/rooms/{CODE}/sec   hk (host key), pk/{pid} (player keys), px/{proof} (used proofs)
```

Every write carries a fresh random proof number and, in the same update, stores the writer's key under `sec/px/{proof}`. The rules allow the write only if that proof did not exist before and now equals the key on file (`sec/hk` for the host's controls, `sec/pk/{pid}` for a player's own entry and answers). Only someone who knows the key can do that, and each proof works once. The rules are generated by `scripts/play-rules.mjs` because the same two conditions are needed at several depths; the header of `src/play/room.js` has the full shape.

What that does and does not protect:

- A stranger cannot run someone else's game, change scores, rename or impersonate a player, or answer twice.
- Answers are readable in the database while a round is open (there is no sign-in to hide them behind). The page never shows them before the reveal, and the true figures are public data anyway. This is a party game, not an exam.
- Room codes are free again a day after a room was made.

## Files

```
src/play/
  main.js        boot, screens, wiring
  engine.js      the rules: which questions, the truth, scoring, awards, the daily game, names
  room.js        the live protocol: Host and Player over a store
  store.js       the store interface, plus the in-memory hub used by tests and ?mock
  fb.js          the store over Firebase Realtime Database (its own chunk)
  views.js       the HTML of every screen
  strings.js     every word, English and French
  settings.js    admin settings: defaults, cleaning, join links
  cloud.js       Firestore over REST (settings, emails, game records)
  admin.js       the admin screen (its own chunk)
  qr.js          QR code as SVG; vendor/qrcode.mjs is qrcode-generator (MIT), unchanged
  fx.js          sounds, haptics, count-up, confetti
  config.js      public Firebase web config
  page.html, styles.css
scripts/
  build-play.mjs   builds the page (called by build.mjs)
  play-rules.mjs   writes the room rules into database.rules.json
test/
  play-engine.test.mjs   questions, scoring, awards, daily game, names
  play-room.test.mjs     a whole game in memory; with `targaryen` installed, replayed against the real rules plus 60-odd things the rules must refuse
```

`npm run test:unmet` runs them all. The rules test is skipped unless `targaryen` is installed (`npm i --no-save targaryen`); it is not a dependency of the site.

## Changing the game

- **Questions and wording**: `strings.js` (`q.{need}`) for both languages. A new need in Unmet's `needs.js` needs an entry there.
- **Scoring**: `SLOPE`, `MAX_POINTS`, `plan()` in `engine.js`.
- **Timing**: `GRACE_MS`, `EARLY_MS`, `REVEAL_MS` in `room.js`.
- **Rules**: edit `scripts/play-rules.mjs`, run it, run the tests, deploy `database`.

## Before launch

- The page has `<meta name="robots" content="noindex, follow">`, like Unmet. Remove it in `src/play/page.html` when you want it indexed.
- There is no social preview image yet (`og:image`).
- Have someone review the French.
